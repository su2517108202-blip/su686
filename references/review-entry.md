# 三模块模板使用与审核

日常交付沿用包内[制作工作台](../assets/templates/workbench.html)及A/B/D版式，不另起一套UI。复制以下六个文件到本轮交付目录并保留相对位置：`workbench.html`、`A.html`、`B.html`、`D.html`、`ui.css`、`ui.js`，来源均为`assets/templates/`。它们是真实可复用静态模板，无模板引擎、后端或外部库；示例材料不是项目成品。

## 页面与布局

工作台顶部显示剧名，左侧220px为A/B/D导航，右侧同一个named iframe `production-workspace`，初始D；窄屏三模块导航横排在顶部。A/B/D均可独立打开并互链。只交付这三个模块，不加C或行政表单。

| 页面 | 填入当前定稿的内容 |
| --- | --- |
| A 大纲与关系树 | 主题、主线冲突、故事走向与结局，整齐的人物关系块 |
| B 角色场景物品生成 | 共同美术及相关角色/服装、场景空间、关键物品；横向行卡左侧身份与摘要，右侧完整生图提示词，窄屏堆叠 |
| D 分镜与视频提示词 | 本集概览、唯一已选模型/模式及SEG卡；动作和镜头时段摘要、素材准备状态，一个复制按钮和一处默认收起的全文 |

沿用轻色底、约16px正文与舒适行距，色值与响应式布局以`ui.css`为准。页面显示本集制作材料，不增加字节表、审计历史、质量报告或旧集原文。复制按钮直接操作剪贴板，不另设手动复制或txt下载路线。

## 填充与DOM契约

执行方读取本集相关上游，复用已认可材料、补必要缺项，再把同一版定稿材料填入这套页面。按本集集中完成文字和HTML后一次交审；用户不用重复填写整部原作或行政材料。

- 每页的`script#su686-data[type="application/json"]`为本页静态数据，`body[data-page]`区分工作台或A/B/D。`[data-project-title]`读取剧名；A的故事与关系块直接填正文，B的`#asset-list`读取`assets`，D的`#segment-list`读取`segments`。小JSON只是本套UI的实现，不是强制项目文件格式或新必填表单。
- 修改真实剧名时，同步HTML的`title`与页内材料。若修改页面文件名，同步`ui.js`的固定`MODULE_FILES`、全部导航href和iframe src；CSS/JS路径亦保持有效，不把任意URL写入模块消息。
- 嵌入时可收起重复独立页头，独立打开则保留导航。消息类型固定`su686:module`；工作台验证`event.source === iframe.contentWindow`及A/B/D白名单，再映射到固定本地文件。消息不接受任意URL或动作。
- B每项完整生图提示词自足，含共同美术和当前版本；素材名与具体衣着相属，实际状态如实填。通过textContent或textarea.value显示提示词，材料不执行为HTML。

## 一份分镜，一次直接复制

D每个SEG只存一份完整modelPrompt，按本轮唯一已选模型/模式一次定稿。每卡只保留一枚`复制分镜提示词`按钮和一处默认收起全文；按钮直接复制modelPrompt，只读textarea亦直接显示这个值，逐字一致，不在点击时包装、插入引用或构造新正文。

正文最前只放极短两句条件用途：静态图片任务取原Shot已有动作阶段生成一张3×3剧情九宫格，只用已有角色/场景/物品参考，不引用待生成九格自身；视频任务使用预定稳定名九格作镜头参考，按原Shot时序输出正常连续单画面视频。初次定稿就在正文中以不带@的普通稳定文件名明确待生板仅作视频参考，不列入生图自动挂载；后面的完整分镜为两种任务共同使用，不另写长九格剧情、另一套动作或固定三镜各三格。

模板仅保留`boardReferences`的最小板名、生成与绑定状态，用于正文外准备度说明。人物/场景/物品另由现有assetReadiness说明；状态是交付时记录，不参与正文拼接、不限制复制。用户按固定名生成九格并在实际平台挂载后，直接使用同一份既有分镜提示词生成视频，无需回填本页。

此通用中文例子不代表H3或任何具体模式合法提交。真实项目按已选模式实际语言、合法标签和引用位置安排条件用途与参考，初次定稿完成；已有subject_definitions等区块时使用适用区块，引用不塞入non_diegetic_music，不据错图反写原剧情。具体创作和状态继承见[分镜](director.md)。

剪贴板API失败时可在内部自动尝试临时textarea回退；仅API完成或回退明确成功才显示成功，两种方式均失败明确提示，不假成功。不另加按钮、手动复制或txt下载路线。

## 统一审核

主监工只读审核、反馈和统一验收，生产性写入与制作由子/执行窗口完成。执行窗口可直接调用工具或用不重叠内部助手，同文件同轮一位实际写手，必要保存/参数/执行结果检查由执行方完成，不再组织另一层质量审核。问题给位置和验收标准，退给原执行者整改，监工不接管制作。

文字检查包括台词/speaker、服装版本名/具体衣着/素材相属、空间朝向与路径、控制权、格与Shot映射、SEG时长，以及全文显示与唯一复制是否直接读取同一modelPrompt。同场连续板核上一认可终态到下一起态；转场与时跳依本场基准和定稿选择起态。仅用户主动要求校准或反馈图像问题时，定位参考冲突，或正文缺失/矛盾的空间、起终态、动作约束，定向修生图输入/提示词规则后验证图；保留已确认剧情、动作顺序、台词与切点，不用错图反推新分镜，拒绝同稿抽卡，不自动追加生成。

如实区分本地逻辑检查、真实浏览器复制交互和媒体观察的覆盖。文字一致不证明实图、表演或视频效果正确；真实图、视频和声音由唯一监工验收。少量必要证据放项目与技能发现目录之外的可见目录，不增加用户必读报告。
